# 引用整个工作台

默认引用 https://github.com/matthewdailytools/codexbestpratice 的完整工作台，先获取并阅读其中的 WORKBENCH.md。不要让用户 clone 仓库、安装单个 Skill、复制文件、输入工具路径或手动执行命令。

## 选择模式

用户已指定“默认”或“引导”时直接采用，否则只提供一次两项选择：
- 默认应用：推荐配置，自动完成环境准备、获取、安装和验证。
- 引导设置：收集会影响结果的项目配置，再自动完成相同操作。

模式选择即授权对当前项目完成规范接入。展示具体差异与操作摘要后自动应用，不增加第二次日常确认；重大范围变化、真实权限阻塞或保护冲突仍按实际情况处理。不要覆盖本地冲突或绕过平台权限。

## 自动完成

1. 从当前项目上下文确定目标目录，读取已有规则、清单与状态；无需询问机器上的工作台位置。
2. 复用现有 Python 3.11+；缺失时按 WORKBENCH.md 的环境准备要求，通过可信来源自动安装必要环境。不要替换系统默认 Python 或改动全局 Codex 配置。
3. 从 GitHub 获取独立入口 workbench.py 到系统临时目录，自动调用它获取整个工作台。首次引用也不依赖已安装的本技能或 Git。
4. 默认模式调用 `python <临时入口>/workbench.py --target <当前项目> --mode default`。路径用独立参数传递，入口会固定 GitHub commit，展示真实差异，保护已有文件，自动应用并检查。
5. 引导模式将 project_name、stack、checks、boundaries、enabled_ids 等答案写入临时 JSON，调用同一入口并传入 `--mode guided --settings <临时JSON>`。能从项目确定的信息直接推导；验证命令不确定就标为待补充。
6. 报告规范版本、来源 commit、安装检查与技能入口，不把内部命令作为用户的操作步骤。checks.confirmed 仅表示命令入口已核实，不表示测试通过；接入不执行项目命令。

## 后续操作

- 升级：同一入口 `--action upgrade`，重新检查 GitHub。
- 修改配置：`--action configure`，固定已安装 commit，避免隐式升级。
- 检查：`--action check`。
- 打开整个管理台并关联当前项目：`--action open`。
- 只有用户明确要求离线或本地草稿时才使用本地源；网络获取失败时说明具体阻塞，不静默换源。

初始默认安装整套启用规范；用户明确限制范围时保留其要求。不从接入授权推导其他外部动作的权限，提交或推送仍遵循当前任务的用户授权。
