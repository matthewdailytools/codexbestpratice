# 实现与验证

读取相关代码、适用指令及现有任务计划；存在冲突时以当前用户目标和实际仓库事实为准。

按既有结构完成最小完整实现，不因复用本技能更换技术栈、工具链或增加无关依赖。保护用户已有修改。

需要验证时，按需读取 `.codex-bp/project.json`：优先核对 checks 对应的真实脚本、工具配置与 CI。confirmed=false 的命令仅是建议；结合证据确认后再运行。没有测试入口时明确说明，并选择可执行的检查，不编造命令或通过结果。

覆盖与改动风险相关的正常、失败和兼容路径。轻微文案修改可人工核对，不新增无意义测试。验证失败要分析、修复或明确报告，不能靠删除测试获得通过。

完成后审阅实际 diff，报告结果、验证与剩余限制。长任务按需更新已有 Markdown 记录；可参考 `.codex-bp/templates/verification-record.md`。
