# 后端开发

先核实业务目标、调用方、信任边界、现有语言框架、部署形态与数据存储。按首版需求划分职责，复用现有结构；不为简单服务强制引入微服务、缓存、消息队列或 Kubernetes。

## 接口与权限

- 明确请求和响应契约、字段类型、缺省值、错误语义、分页与兼容行为，沿用项目协议与版本方式；HTTP API 使用与语义一致的方法、状态和缓存行为。
- 在服务端校验类型、大小、范围和可写字段；身份来自可信认证上下文。每次数据访问验证对象、操作和租户权限，不能信任请求中的 user_id、tenant_id 或前端隐藏按钮来授权。
- 按应用形态处理会话、CSRF、CORS、上传、外部 URL 和路径访问；数据库使用参数化查询或等效安全入口，错误响应不泄露凭据、内部堆栈和敏感业务数据。

## 数据与一致性

- 明确业务不变量、唯一约束、事务范围与状态转换，覆盖失败回滚、并发和重复请求。金额、时间及时区采用明确表示，避免隐式浮点或本机时区假设。
- 会产生副作用的重试、支付或异步消费按实际需要设计幂等。幂等键绑定调用身份与请求语义，去重和业务结果原子记录；同键不同请求不能悄悄复用错误结果。不能只加一个内存集合就宣称跨进程或重启安全。
- 数据迁移说明新旧调用方兼容、回填、验证与恢复方案；按风险使用分阶段扩展／收缩，破坏性生产变更遵循实际授权，不把生成迁移脚本当作已执行。

## 可靠性与运行

- 对外部调用设定超时、可取消行为和有界重试；只有确认可安全重复的操作才重试，结合退避与上限。分页、并发、请求体、文件与昂贵计算有适当资源上限，避免无界队列与全表读取。
- 缓存明确一致性、失效和故障降级；异步任务明确重复投递、失败重试、取消及状态可观察性。仅在真实需求支持时增加相关基础设施。
- 配置和密钥通过项目既有环境／安全存储注入，提供无真实秘密的示例。日志结构化并关联请求，敏感字段脱敏；依据服务形态提供适用的错误、延迟、健康与依赖状态信息，避免每个简单模块都增加完整监控栈。

## 验证与交付

针对本次变化选择单元、契约、数据库／接口集成或端到端验证，实际覆盖授权失败、跨用户／跨租户、非法输入、冲突、重复与并发、外部失败和迁移兼容中适用的路径。沿用真实数据库与测试设施；模拟测试不冒充真实集成或压力结果。

交付说明 API 行为、配置入口、数据兼容、实际检查和未验证限制；真实服务启动、生产数据操作与发布各自依据授权，不能仅凭一份设计或通过的单元测试宣称服务已经上线。

依据：[OWASP API Security](https://owasp.org/projects/api-security-project)、[OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/)、[HTTP 语义 RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)。按项目协议和风险选用相关要求。
