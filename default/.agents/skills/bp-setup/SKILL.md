# 项目初始化与规范检查

先读取当前项目 AGENTS.md、README、工程清单、工作区状态与 `.codex-bp/project.json`。规范已随文件包复制到当前项目，不要求用户获取远程工具、配置版本频道或重复执行安装。

1. 确认项目用途、目标平台、技术栈与目录职责。能从代码查证的直接查证，关键业务未知集中澄清，用户已给定的信息不重复索要。
2. 检查 AGENTS 的章节引用、相关 Skills 和模板存在，读取实际任务适用规范；不把 VERSION_NOTES 的复制说明当作业务需求。
3. 核实真实运行与验证入口，再更新项目配置的已知事实；未知命令保持待补齐。confirmed 仅表示入口核实，不代表测试执行或通过。
4. 已有项目保留原 AGENTS、同名技能、配置和任务记录。遇到同名冲突先比较并合并已授权内容，不整目录覆盖或删除用户文件。
5. 在新的 Codex 运行确认项目指引加载；有发现接口时核对相关技能路径和 repo 作用域。文件存在、运行时发现、实际读取和行为遵循分别报告。

新项目采用最小适用目录，不预建无用途数据库或部署设施。复杂任务按需建立 goals/ 与 plans/ 的同名互链记录；已有任务来源继续使用。

规范维护通过工作台新建整套副本；业务开发不要顺手改写规范。工具、依赖和外部服务仅在真实任务需要且授权时准备，不修改全局 Codex 配置。
