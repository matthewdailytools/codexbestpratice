# iOS UI 与交互

先核实 iPhone 目标、最低系统版本、现有 SwiftUI／UIKit／跨平台工程、品牌和核心任务。沿用已选工具链；使用新系统组件前核实可用版本，不为视觉更新擅自提高最低版本。

- 先列主要屏幕、信息层级和关键操作，统一语义颜色、文字层级、间距与组件状态。优先平台标准组件和现有设计系统，品牌表达服务内容，不复制其他平台的窗口或返回习惯。
- 使用适合任务的导航栈与稳定顶层入口，保留系统返回和边缘返回行为；模态只处理有边界的短任务，提供清晰完成与取消，不靠连续弹层代替层级导航。
- 适配安全区域、软键盘与输入焦点，验证键盘弹出后字段和提交仍可操作。主要触控目标优先达到 44×44 pt 的舒适尺寸，视觉图标可以较小；紧凑控件的例外须核实平台指引和实际可操作性。
- 使用可缩放文字和语义布局，检查较大 Dynamic Type、深浅主题、对比度和减少动态效果。VoiceOver 名称、角色、状态和阅读顺序表达业务含义，不能只靠颜色、图标或手势说明结果。
- 关键流程明确加载、空内容、成功、失败、离线与恢复；错误保留可用输入，重试不产生重复提交。权限在需要时请求，拒绝后提供可理解替代路径；原型的模拟数据明确说明。
- 验证代表性窄屏、支持的方向、大字体、VoiceOver 和前后台恢复，以及返回、取消、重复点击与网络失败。只使用当前可用的构建、模拟器和设备入口；静态审查不能报告为真机验证。

依据与版本核对：[Apple iOS HIG](https://developer.apple.com/design/human-interface-guidelines/designing-for-ios)、[Apple 可访问性](https://developer.apple.com/design/human-interface-guidelines/accessibility)。项目具体版本和设计要求优先核实。
