# 变更评审

先确定评审范围并读取实际差异及相关调用方、测试、约束；避免假设已安装的工具或不可用的外部服务。

优先检查行为错误、数据损坏、权限边界、兼容性和失败处理。只报告有证据、可定位且有实际影响的问题，说明触发条件、影响、位置和可行修复方向；不要用风格偏好填满报告。

将需求验收与实际实现逐项对照，检查相关调用方和验证证据。必要时运行最小复现；无法复现的推断标明依据和不确定性，不用笼统检查清单代替具体发现。规范评审还要检查触发范围、指令冲突、重复规则和目标项目的实际加载入口。

区分实际验证与推断，说明未覆盖范围。没有发现时直接说明，并记录剩余验证限制。需要保存时参考 `.codex-bp/templates/review-report.md`。

默认由当前代理执行评审；不把自查称为独立评审，也不自动创建子代理或向他人发送消息。用户要求修复时继续在授权范围内完成。
