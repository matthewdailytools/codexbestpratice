# Web UI 与交互

先读取产品目标、用户场景、现有页面、框架、品牌和浏览器支持范围。沿用已选工具链；新项目选择与首版复杂度相称的实现，不默认引入后端、登录、支付或额外构建依赖。

- 明确信息结构、核心任务与主要行动，建立一致的字体层级、配色、间距、内容宽度和组件状态，优先已有设计系统。根据内容和品牌选择视觉方向，避免只摆放无实际行为的按钮或以通用演示文案冒充业务需求。
- 按内容需要设置响应式布局，覆盖窄屏、宽屏、缩放和触控；避免无意横向溢出、固定高度裁切、悬浮元素遮挡与禁止缩放。功能不能只依赖 hover、拖动或精细指针。
- 导航使用真实可访问链接，操作使用按钮，输入有可关联标签和合适类型；支持键盘、可见焦点、合理顺序、弹窗焦点往返及 Escape。应用路由按需支持刷新、深链接和浏览器前进后退。
- 将 WCAG 2.2 AA 作为默认设计与验证目标，核实对比度、语义、可访问名称、错误提示、焦点不被完全遮挡和触控目标要求及其例外。自动扫描仅覆盖部分标准，不能据此宣称全面合规。
- 覆盖默认、悬停、焦点、禁用、加载、空内容、成功与失败等适用状态；表单错误靠近字段并保留输入，异步反馈可被辅助技术感知，重试避免重复提交。模拟接口、占位数据和未实现入口明确说明。
- 外部数据按上下文安全编码，避免不可信 HTML 注入；前端验证不代替服务端校验与授权。图片、字体与媒体控制体积和布局位移，动效尊重减少动态效果，性能目标依据项目真实使用场景确定。
- 使用可用浏览器验证代表性桌面与移动宽度、完整主要交互、键盘、加载／错误路径和控制台；相关自动测试、构建按实际入口运行。只有静态代码检查时明确尚未完成视觉或交互验证。

依据：[WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[WCAG 2.2 快速检查参考](https://www.w3.org/WAI/WCAG22/quickref/)。平台数值和合规结论需逐项核实。
