# 八、Git 与变更管理

修改前检查 git status 和相关差异，区分用户已有修改与本轮变更。保留工作区和暂存区，不用 reset、checkout 或清理命令覆盖无关成果。

独立任务保持可审阅变更边界。分支和 worktree 沿用项目策略，确有需要并符合授权时才创建；不强制 develop/release 分支体系。

完成前检查 diff、必要验证和文档。提交、推送、PR、合并与部署根据实际任务授权执行；已有授权不反复询问，本规范不自行扩大权限。

提交命名沿用项目约定。没有历史提交的仓库不能假定 HEAD 存在，按实际暂存区与工作区选择审查基线。没有 Git 时仍需核对修改范围和前后内容，不伪造提交记录。

真实生产变更另核对适用的迁移、监控与恢复准备；生成这些材料不等于已经发布。
