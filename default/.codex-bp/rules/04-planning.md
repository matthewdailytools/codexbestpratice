# 四、里程碑与任务拆分

## 方案与依赖

结合相关代码明确模块职责、调用关系、接口和数据变更、兼容方案、失败处理与风险。沿用既有架构，不擅自加入登录、数据库、缓存或部署设施。

## 里程碑

按真实业务依赖划分可独立验收的阶段；不固定为“数据库 → 认证 → 前端”。每个里程碑记录目标、范围、产物、验收、前置依赖及状态。

需要新的长期记录时使用 goals/ 与 plans/ 同名文件；已有记录持续更新，保留历史证据。未完成实现或验证的目标不能标记达成。

## 独立任务

每项任务说明要解决的问题、涉及模块与文件、范围外事项、依赖、实现方式、验收及验证入口。以能单独审查和验证为粒度，避免无关重构。

并行分工需要实际授权和独立工作收益；先明确契约、文件归属及集成责任。计划应足以让后续实现者继续工作，但不要强制所有小修改新建文档。
