# 三、需求分析

## 四层需求

1. 产品：服务谁、解决什么问题、首版目标与范围外事项。
2. 功能：主要流程、状态、错误、边界、角色和权限。
3. 技术：已有技术栈、接口、数据、运行与兼容约束。
4. 验收：明确输入、操作和可观察结果，列出失败及边界场景。

## 未决问题

仓库和工具可以查到的信息先查证。金额、权限、退款、数据删除、身份来源等关键规则无依据时，列出问题与影响，不把建议写成已确认事实。需要用户决定时集中提问；沉默不等于采用默认业务规则。

用户明确允许默认原型时，说明假设、模拟数据、未接入能力和首版边界，然后推进；不得从原型授权推导生产发布、真实支付或业务数据操作权限。

## 输出与验收

复杂需求按需使用需求模板或续写已有记录。需求至少能回答“为谁做、做什么、边界是什么、怎样算完成”。明确需求直接实施，不为了完成模板重复索取信息。
