# 五、统一任务执行

## 项目分析

从实际代码梳理架构、依赖、模块、数据流、接口、权限、运行与测试方式，区分事实、推断和未知。用户只要求分析或评审时保持代码只读。

## 任务规划

给出需求理解、方案、涉及文件、接口与数据兼容、步骤、风险、验证和验收。用户明确要求“先计划”时保存计划而不编写业务实现；已有实施授权不重复审批。

## 编码实现

先读相关模块及调用方，复用已有功能和约定。实现授权范围内完整行为，处理输入、错误与边界，保留兼容；不留下必需功能的占位按钮或 TODO。按风险补必要测试和说明。

## 评审

读取实际 Git diff、关联代码与验收。报告有证据且可定位的问题，给出触发、影响和修复方向；不编造缺陷。自查与独立评审分别表述。需要保存时使用评审模板。

## 交付

核对实际差异与结果，报告实现、真实验证、未完成项和运行入口。模板提供结构，填写内容必须基于当前任务事实，不能照抄示例中的“全部通过”。
