# 六、测试策略与质量验证

## 核实入口

读取工程清单、测试脚本、CI 和项目配置，核实适用检查。confirmed=false 表示命令待确认，confirmed=true 也不表示执行通过。没有配置的检查明确说明，不虚构命令。

## 按风险选择层次

- 单元／回归：逻辑、输入、边界、失败分支和原缺陷。
- 集成：实际存储、外部服务或模块协作，明确环境与依赖。
- API／契约：请求响应、错误、对象和租户权限、兼容。
- E2E：实际用户入口到主要结果的完整链路。
- 安全／性能：涉及的输入、权限、资源和依赖风险；有目标时使用真实方法测量。

Lint、类型检查和构建使用项目已有入口，适用时运行。轻微文案或低影响调整可直接核对，不写镜像实现或无意义测试。

## 执行与证据

必须查看命令退出码、测试发现数量和结果。零测试不算测试通过；单测或模拟不能冒充真实集成。缺陷先复现，修复后重跑相关检查，必要时扩大验证。

失败要分析、修复或明确说明真实阻塞；禁止删有效测试、改探针或降低标准制造通过。最终分别报告通过、失败、未运行与未配置，记录命令和限制。
