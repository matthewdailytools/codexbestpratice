# 十三、工程配置与完成标准

## 最小项目配置

项目有明确的 agent 入口、用途与运行说明、当前技术栈和目录职责。验证命令来自真实工具配置；必要设计与任务记录按复杂度建立，既有来源继续沿用。

项目需要的接口、存储、认证、迁移、部署和监控由实际需求决定，不因复制默认包就宣称已经具备。

## 任务完成标准

- 已接受需求与边界已实现，正常、失败、边界和兼容行为符合验收。
- 改动范围可解释，保留用户成果，公共接口和数据变化有兼容处理。
- 适用测试和工具检查实际执行，数量、退出码与结论一致；未覆盖项明确。
- 已核对相关代码差异、调用方、安全与数据边界，修复确定问题。
- 必要说明、运行入口和续接记录准确，无必需占位实现或未说明失败。

存在阻塞或未完成项时如实交代，不能为了满足清单伪造全通过。代码完成、测试通过、已提交和已上线是不同事实，分别按证据报告。
