# 二、项目初始化与项目结构

## 项目事实与入口

先读取 README、AGENTS、工程清单、相关代码和任务记录。确认开发平台、语言、运行方式和真实验证入口，更新 `.codex-bp/project.json` 中已知事实；命令未核实就保持待确认。规范复制不会安装运行环境、依赖或 CI。

## 目录职责

- 根目录保持清晰的项目说明与 agent 入口。源码、测试、文档、自动化分别使用当前技术栈的原生布局。
- `.agents/skills/` 保存按需方法；`.codex-bp/rules/` 保存工程规则；`.codex-bp/templates/` 保存任务记录模板。
- 复杂且需要续接的任务，首次需要时建立 `goals/<里程碑标识>.md` 与 `plans/<同一标识>.md`，目标记录验收与达成证据，计划记录步骤、依赖与进度；两者互链。
- 已有 GOALS.md、PLANS.md、Issue 或其他任务来源时继续沿用或建立索引，不强制迁移，不重复维护状态。
- docs/ 或现有文档目录按实际需要保存架构、接口、数据与运行说明。不要预建没有用途的数据库、微服务或部署目录。
- 源码、测试和依赖变动时同步导入路径及必要文档。生成物、真实秘密与本机路径按项目忽略和安全存储约定处理。

## 已有项目复制

复制规范前核对同名文件。已有 AGENTS.md 先合并约定，保留更具体的用户和项目要求；已有同名技能或配置不能直接覆盖。新项目复制文件包后，在新的 Codex 运行中验证加载。
