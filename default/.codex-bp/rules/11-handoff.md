# 十一、日常开发节奏与交接

按一个连贯成果组织任务。复杂工作先明确需求与方案，再实现、实际验证、审查和交付；小任务可以在一次执行中完成。已授权工作持续推进，不因阶段切换重复审批。

目标、计划、决策和验证证据保存在项目文件或既有任务来源，不能只依赖聊天记录。新多里程碑采用 goals/ 与 plans/ 同名互链；已有 PLANS.md 等继续复用。

需要中断或转交时，记录目标、接受的调整、已完成、工作区状态、实际验证、剩余任务和恢复入口。区分必要未完成、可选建议和外部阻塞。

恢复时核对当前代码、配置、git 状态和已接受需求；旧交接的“已完成”必须与实际实现一致，过期记录及时纠正。

交付先给结果和入口，再说明证据与限制。未运行的测试、未接入的接口和未完成的功能不得标为完成。会话是否拆分由任务连续性和用户要求决定，不机械强制每阶段新开聊天。
