# 一、推荐的整体开发工作流

## 根据目标选择流程

- 接手项目先核对当前代码、目录、项目规则和工作区状态。以实际证据判断已实现能力，不能照抄过期说明。
- 用户只给目标且缺少用途、核心用户或关键业务规则时，先集中澄清决定性问题；等待时继续完成独立检查。已有明确需求不重复提问，授权原型按透明假设推进。
- 小而明确的修改直接实现、验证并交付。复杂任务按下面的阶段推进，可合并相邻步骤，避免每一步都变成审批。

## 阶段与交付

1. 需求分析：明确用户、业务行为、范围和未决问题，给出可观察验收。
2. 架构规划：核对现有实现，明确职责、接口、数据、兼容与关键取舍。
3. 项目初始化：准备最小可运行结构、项目事实和实际验证入口。
4. 任务拆分：形成有依赖的里程碑和独立任务，逐项记录范围与验收。
5. 编码实现：完成授权范围内的最小完整功能，保留既有行为与用户修改。
6. 自动化验证：实际执行适用检查，检查发现数量和结果，失败后分析并复验。
7. 代码审查：结合需求、实际差异和调用方查找可复现问题。
8. 交付发布：说明成果和证据；提交、推送、生产部署分别遵循实际授权。

## 推进要求

按“规划 → 实现 → 验证 → 评审 → 交付”形成闭环。已获授权且仍可推进的必要工作继续完成；不要用计划或交接替代尚未完成的实现。
