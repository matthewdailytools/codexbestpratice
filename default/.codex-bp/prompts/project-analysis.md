# 项目分析 Prompt

请分析当前项目，结论以实际代码和配置为依据。

## 输入与边界

- 分析目标：[填写关注点]
- 输出位置：[默认对话输出；需要保存时填写 Markdown 路径]
- 本轮不修改业务代码、依赖和项目配置，不重置、暂存或提交工作区；仅在指定了输出路径时保存该分析报告。

## 执行要求

1. 阅读 AGENTS.md、README、docs/ 或既有说明、工程清单和当前 git 状态。
2. 梳理技术栈、目录职责、模块及依赖关系，核实实际运行和测试入口。
3. 按存在的能力梳理数据、API、认证授权及主要调用链；不存在的组件明确标明，不凭空补全。
4. 从关键代码、调用方和测试识别有证据的问题，说明位置、触发条件、影响和验证限制。
5. 不确定结论标为推断或待确认。未运行的检查不得称为通过；需要写入或外部操作的验证先按本轮边界处理。

## 输出

项目现状、核心模块关系、关键路径、运行与验证方式、已发现问题、风险和按优先级排列的改进建议。每项重要判断应能追溯到文件或实际检查。
