# 架构规划 Prompt

请根据已接受需求形成技术方案，本轮不编写业务实现。

## 输入

- 需求与验收：[填写或引用现有需求]
- 已选技术栈：[填写，未知则基于现有工程核实]
- 约束：[填写兼容、数据、部署或规模约束]

## 执行要求

1. 阅读 AGENTS.md、相关模块、调用方、接口、数据与现有测试，确认真实能力。
2. 给出最小适用目录和模块职责，说明调用关系、接口契约、数据归属与信任边界。
3. 涉及存储时明确不变量、事务、并发与迁移；涉及外部调用时明确超时、失败与适用的重试或幂等。
4. 沿用已有技术和结构。只有真实需求支持时引入数据库、缓存、队列或分层，给出选择理由和兼容影响。
5. 按实际平台读取专项技能；关键业务未知继续列为待决，不用架构假设代替业务决策。

## 输出与验收

现状与目标、模块／目录职责、接口和数据方案、主要流程、兼容／迁移、取舍与风险、验证方案和实施依赖。图示只用于解释实际方案，不虚构不存在的组件。
