# 代码审查 Prompt

请评审当前指定差异，先给审查结果，不直接修复业务代码。

## 输入

- 审查范围：[默认当前 Git diff，或填写明确基线与文件]
- 需求与验收：[填写或引用]
- 关注约束：[填写兼容、数据、安全或性能要求]

## 执行要求

1. 阅读实际差异、相关调用方、约定和测试；无 HEAD 时根据实际暂存区与工作区选择基线。
2. 优先查找行为错误、数据损坏、对象／租户权限、兼容破坏、并发、资源和失败处理问题。
3. 对照验收和实现，必要时执行不改变业务代码的最小复现；区分静态判断、实际复现与未验证推断。
4. 仅报告有依据、可定位且有实际影响的问题；不把风格偏好或猜测当成确定缺陷。
5. 每项给出严重程度、文件与位置、触发条件、原因、影响和修复方向；测试失败如实记录。
6. 当前代理自查就标明自查；只有明确授权且实际由独立执行者完成时才称为独立审查，不自动创建子代理。

## 输出与验收

按严重程度列出发现，说明证据、审查范围和限制。没有发现直接说明；需要保存时使用评审报告模板，不编造问题填满清单。
